# Changelog

All notable changes to CorpusKit are recorded here, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Releases use calendar versions, `YYYY.M.D` without zero padding and tagged `v2026.9.27`, with a `.N` suffix for a second release on the same day. Release dates are in Australian Eastern time. How a release is cut is in [docs/RELEASING.md](https://github.com/noicework/corpuskit/blob/main/docs/RELEASING.md).

Each release groups its changes under Added, Changed, Fixed and Security, then closes with Upgrade notes for people who run a deployment: new or changed settings and their defaults, behaviour that changes on upgrade, changes to stored data, and whether rolling back is safe.

## [Unreleased]

### Added

- Agent ask: one answer, streamed step by step, across a portal's own collection and its federation peers, or across several portals. `POST /api/t/:slug/ask-agent` answers over one portal and its peers. `POST /api/ask-agent` answers over the portals named in `slugs` (up to 12), or every portal in the caller's directory, authorised and admitted as the federated ask (`/api/ask-estate`) is, and is not served on a portal's own hostname. The stream sends `agent-start`, `agent-step`, `agent-sources`, `reasoning`, `delta`, `citation` and `sources-failed` events, then `done` or `error`. A portal opts in with `{"agentAsk": true}` through `PATCH /api/admin/tenants/:slug`; otherwise both routes answer 404. With no retrieval agent to answer, which is every portal today, the portal composes the answer itself (`mode: "orchestrated"`): it searches each collection with a 20-second limit, names any that failed in `sources-failed` while the rest still answer, writes one answer and checks every citation against its passage, and declines an answer left with no supported citation. The one-portal route counts as one ask and the cross-portal route once per portal it reaches. There is no reader page or Manage screen for it yet. See [Agent ask](https://github.com/noicework/corpuskit/blob/main/docs/AGENT-ASK.md). ([#134](https://github.com/noicework/corpuskit/pull/134))
- Federation peers: a portal's composed answers can also search partners' Progress Agentic RAG knowledge boxes, set as `federation.peers` through `PATCH /api/admin/tenants/:slug`. A peer of kind `arag-kb` is searched through the box's retrieval only, never a generative call, and one of kind `arag-mcp` through its MCP server's `search_documents` tool. Each peer's read-only key is stored with `PUT /api/admin/t/:slug/federation/peers/:peerId/key` (the operator credential or `bindings.write`), sealed with `BINDING_KEY` and never returned. A peer call can reach only the box's search path or its read tools, at an address built from the peer's zone and box id alone, and redirects are refused. Each call has the same 20-second limit as any source, counts as one more ask against the host's rate limits and is audited as `federation.peer.call`; a peer that fails, times out or refuses its key is named in `sources-failed`. A partner's citation links to its origin only when the peer sets `linkOrigins: true`, and otherwise shows its title, label and passage. ([#134](https://github.com/noicework/corpuskit/pull/134))
- A portal can stay out of other portals' federated answers. `{"federation": {"participates": false}}` through `PATCH /api/admin/tenants/:slug` leaves it out of other portals' composed answers, federated asks (`POST /api/ask-estate`) and the estate MCP tools (`/api/estate/mcp`) before anything is asked or counted, and stops it federating to its own peers; its own agent ask is unaffected. The change is audited as `tenant.behaviour.update` with `participates` and `previousParticipates`. A document labelled `federation/exclude` (label set `federation`) is dropped from another portal's composed answer and from any peer's results, and still answers in its own portal. ([#134](https://github.com/noicework/corpuskit/pull/134))
- For integrators: `AgentAnswerExportButton` (`apps/web/src/components/AgentAnswerExport.tsx`) saves agent ask answers as a Word document, an evidence brief: each question, who wrote the answer, what every collection gave, the answer with its citations renumbered by first appearance, and the references grouped by collection, followed by the collections that could not be searched and why. A federated partner is named as one, its passage is quoted where it has no link, and a partner that refused its key is listed as one that could not be reached. It needs `portal.export`, like the Ask page's export. No page mounts it yet. See [Saving an answer as an evidence brief](https://github.com/noicework/corpuskit/blob/main/docs/AGENT-ASK.md#saving-an-answer-as-an-evidence-brief). ([#120](https://github.com/noicework/corpuskit/pull/120))
- Manage > Content > Link health lists the portal's website-source pages and document origin links that failed a check, drafts and failed ingests included. Restricted (401 or 403), temporary and timed-out links are reported apart from missing pages (404 or 410), and nothing is deleted automatically. A curator can check on demand, re-check one result, ignore it until it is re-checked, or retire the document through the existing delete. Daily maintenance checks links too. Each run checks at most 100 links, oldest first, within 65 seconds, with a 10-second limit for each request and 500 ms between requests to one host. Routes are under `/api/admin/t/:slug/link-health` (`content.write`). ([#129](https://github.com/noicework/corpuskit/pull/129))
- Website-source syncs refresh the pages they already hold. Within `maxPages` a run revisits known pages, skips unchanged ones by ETag, Last-Modified or a hash of the extracted content, and replaces changed ones through clean-text ingestion, keeping their title, topic labels and draft state. A failed fetch leaves the existing page as it was. Source summaries count new, changed, unchanged and failed pages. ([#129](https://github.com/noicework/corpuskit/pull/129))
- Each portal can keep evaluation sets in Manage > Evaluations: up to 20 research questions a set, each with the sources it should find and optional facts it should state, or marked to be declined. A set runs on demand or on a daily or weekly schedule, through the portal's own search and ask, so its permissions, audit and daily ask limit apply. A run reports retrieval hits against the expected sources, citation precision, answer quality, decline correctness and expected-fact coverage separately, with no combined pass mark, keeps a snapshot of its set so runs can be compared, and downloads as CSV. Starting a run or a schedule asks the administrator to confirm its ask count, and a run the day's remaining asks cannot cover is refused. Routes are under `/api/admin/t/:slug/evaluations` (`behaviour.write`). See [Portal evaluations](https://github.com/noicework/corpuskit/blob/main/docs/EVALUATIONS.md). ([#128](https://github.com/noicework/corpuskit/pull/128))
- Every new answer leaves a record of the evidence and checks behind it. Portal Ask, search answers, document chat and each portal's answer to a cross-portal ask save the question, the retrieval queries, the retrieved and cited passages with their pages and scores, the verification results (citations kept and dropped, sentences checked, figures removed), the model and configuration identifiers with hashes of the prompts, never the prompts themselves, and quality, timing and token counts. Credentials, session ids, IP addresses and URL query strings are redacted, and a record is at most 384 KiB and marked when it is truncated. The record is saved before the answer completes, so a failed save fails the answer. Curators (`content.write`) see an "Answer record" link beside each completed answer, opening `/t/:slug/answer-records/:id`, and can export that record, or every record in a date range, as JSON or CSV with formula-safe cells, under `/api/admin/t/:slug/answer-records`. Records are kept 90 days by default; a portal administrator (`behaviour.write`) sets 1 to 365 days with `PUT /api/admin/t/:slug/answer-records/retention`, and daily maintenance purges expired records. Existing answers are not backfilled. See [Answer records](https://github.com/noicework/corpuskit/blob/main/docs/ANSWER-RECORDS.md). ([#127](https://github.com/noicework/corpuskit/pull/127))
- Curators can review likely duplicates and versions of a document in Manage > Duplicates and versions (`GET /api/admin/t/:slug/duplicates`, with `POST .../refresh` and `POST .../review`, all needing `content.write`). Each candidate pair shows why it was flagged: a shared title, a shared source address or high similarity in the listed metadata, with different publication dates marked as a possible version. "Not a duplicate" and "Keep both" are remembered for the pair and audited as `duplicate.review`, and "Retire one" opens the existing delete confirmation. Nothing is chosen or removed automatically. Platform administrators get Knowledge boxes > Collection overlap at `/admin` (`GET /api/admin/overlap`, with `POST .../refresh` and `GET .../export`, needing `portal.create`): for each pair of portals, the counts of shared titles, shared addresses and similar pairs with examples, 50 pairs a page, and a CSV of the page with its cells escaped against spreadsheet formulas. Reports read only the listed metadata and are kept in memory for a day. See [Duplicate review and collection overlap](https://github.com/noicework/corpuskit/blob/main/docs/DUPLICATE-REVIEW.md). ([#124](https://github.com/noicework/corpuskit/pull/124))
- The header search, and the hero's ask field that shares it, suggests as the reader types: matching document titles, the portal's topics and its suggested questions, then a row to search for the text and one to ask it. A document opens its page, a topic opens the Library filtered to it and a question opens Ask. The browser fetches the portal's titles once a session from `GET /api/t/:slug/titles` (`portal.read`, a bounded read of the cached catalogue) and matches them itself, so no keystroke reaches the server or the knowledge box. The list is a combobox: Up and Down move, Enter takes the highlighted row or searches for what was typed, Escape closes and then clears, and the number of suggestions is announced once the list settles. ([#123](https://github.com/noicework/corpuskit/pull/123))
- Manage > Content > Recent additions can update a document's text. "Update and re-index" takes the full replacement text, at least 80 words, and sends it to the existing `POST /api/admin/t/:slug/reingest`: a new text document is indexed and the original is removed, keeping its title, source address and draft status. Saved citations still point at the original. It needs `content.write`, as the route does, and adds no route or setting. ([#122](https://github.com/noicework/corpuskit/pull/122))
- Portal administrators can download one portal's inventory, configuration and audit as a ZIP from `GET /api/admin/t/:slug/export`, which needs `audit.export` and refuses MCP keys. The bundle holds a manifest, the portal's configuration, every resource (drafts and failed ingests included) with its metadata, labels and portal file links, its label sets, its MCP keys without any key material, its audit log as CSV, and its insights and routing records. Reader feedback is left out unless the request adds `?includeFeedback=true`. Credential fields and tokens are removed, and a portal over 8 MiB, 10,000 resources, 20,000 audit events or 5,000 routing records gets 413, never a partial bundle. Each download is audited as `portal.export.bundle`, with the feedback choice. See [Portal export bundle](https://github.com/noicework/corpuskit/blob/main/docs/PORTAL-EXPORT.md). ([#121](https://github.com/noicework/corpuskit/pull/121))
- An AI agent can search and ask across several portals through one MCP endpoint, `/api/estate/mcp`, with two read-only tools. `search_estate` returns one ranked list, each result tagged with its portal; with `answer_estate` each portal answers from its own documents with its own verified citations, and every answer and citation names its portal. A portal key reaches other portals there when it is minted with an `estate` of up to 19 portal slugs through `POST /api/t/:slug/mcp/keys`. Its creator must hold the key's role on each, and on each the key gets the lower of its own role and the creator's current one. Revoking or expiring the key on its own portal ends it everywhere, and other portals' own MCP endpoints still refuse it. A signed-in user reaches the portals in their portal list. A portal that fails, times out, answers without a verified citation or is unavailable is listed in `failed_sources` with a reason, and the others still return. Every call writes an `estate.query` audit row in each portal it reached, and an answer counts once on each portal toward its daily asks and the caller's ask limits. Manage does not show or set an estate yet; estate keys are minted through the API. See [Estate MCP endpoint](https://github.com/noicework/corpuskit/blob/main/docs/RBAC.md#estate-mcp-endpoint). ([#118](https://github.com/noicework/corpuskit/pull/118))
- The knowledge graph can be used without dragging it or watching it move. A Pause / Play control stops the 3D map's drift, and with reduced motion set the map starts still. A Map controls panel has buttons to rotate, pan, zoom and fit either map, and the keyboard does the same once the map has focus: in 2D the arrows pan, + and - zoom and Home fits; in 3D the arrows rotate, Shift with the arrows pans and Enter selects the nearest item. A Map / List switch shows every item as a text list with its category, counts and relationships, each linked to the Library, and readers who prefer reduced motion start on the list. The Library now reads `?q=`, so an item's link opens the Library searching for it. ([#117](https://github.com/noicework/corpuskit/pull/117))
- A citation opens the PDF at the page it cites, with the passage highlighted. Each citation now carries the text and page of the first paragraph the answer cited in that document, and every citation link follows it: Ask markers and chips, search answers, document chat, answer journey stops and saved investigation passages, which keep the page. Without a page the reader finds the passage in the PDF's text, and a PDF made from an Office document says when the passage is not on the cited page and offers to find it. On arrival focus moves to the page, never out of a field someone is typing in, the page change and the highlight are announced, and the arrow keys turn pages. ([#116](https://github.com/noicework/corpuskit/pull/116))

### Changed

- The Ask page's sources rail shows one heading, "Sources found: N". The "Sources for the latest answer" line above it is no longer shown and stays the rail's name for screen readers. ([#132](https://github.com/noicework/corpuskit/pull/132))
- The hero's question chips are a nearly opaque surface chip with ink text, a trailing arrow and a 1px edge, in place of a heavy accent fill, so they read on every palette. ([#123](https://github.com/noicework/corpuskit/pull/123))
- For contributors: CI runs its checks as jobs that run at the same time instead of one after another, on pull requests and before a deploy: typecheck, lint and format (`deno task check:static`, new), the unit tests in three shards and the browser E2E suite in eight, so a pull request's checks take about 3 minutes instead of 21. `deno task check` still runs all of it locally. `e2e/support/shard.ts` balances the files by their measured run times, and Deno's module cache is kept between runs. A shard whose tests fail runs the failing files once more and passes only if that second run does; more than three failing files, or no test report at all, fails it at once. Each file run again is listed in the job summary, and one that passed the second time is marked as a flaky test on the run. ([#113](https://github.com/noicework/corpuskit/pull/113), [#126](https://github.com/noicework/corpuskit/pull/126))
- Deno fences `DATA_DIR` and every persistent store it writes, each with its own writer lock: a sibling lock for each portal, binding, knowledge graph proposal and RBAC SQLite file, and one for the branding directory, including stores inside `DATA_DIR`. Servers with different data roots cannot write a shared file concurrently, distinct files can still share a folder, existing paths and explicit overrides are unchanged, and lock timeouts name the held path. ([#108](https://github.com/noicework/corpuskit/pull/108))
- Development and self-hosting instructions require a separate port and isolated storage per server: its own `DATA_DIR` and store paths, or a separate working directory. `TENANTS_PATH` and `BINDINGS_PATH` keep their `./data` defaults when `DATA_DIR` changes, so changing that directory alone still shares files and is refused. ([#108](https://github.com/noicework/corpuskit/pull/108))
- The figure check no longer accepts a document's generated summary or key takeaways as evidence. A figure only the summary carries is removed like any other unverified figure, and an emptied answer is never rescued with a sentence from a summary. ([#76](https://github.com/noicework/corpuskit/pull/76))
- The home page, About, the README and the structured data describe the project in one line: CorpusKit, the open source research portal for Progress Agentic RAG. The structured data names the repository and corpuskit.cloud as the same project and Noice's LinkedIn page as the same organisation, and the home page and About link CorpusKit Cloud, the hosted service. ([#75](https://github.com/noicework/corpuskit/pull/75))
- The website serves its own fonts instead of loading them from Google Fonts, so the first paint no longer waits on a third-party stylesheet. The fonts are under the SIL Open Font License (`apps/web/public/fonts/OFL.txt`). ([#75](https://github.com/noicework/corpuskit/pull/75))
- The reference deployments set `PORTAL_INDEXING=deny` in `wrangler.jsonc` and `wrangler.demo.jsonc`, so their portals stay out of search while the home page, About and documentation stay indexable. ([#75](https://github.com/noicework/corpuskit/pull/75))
- The documentation overview is titled "CorpusKit documentation", and the home page's description names the licence and the checked answers. ([#74](https://github.com/noicework/corpuskit/pull/74))
- `/api/health` reports `release`, the newest release the build contains. On Cloudflare it now also reports `buildSha` and `builtAt`, the commit and time the build was made, as the local server already did. ([#73](https://github.com/noicework/corpuskit/pull/73))

### Fixed

Every other error, the 412 for `max_tokens` included, is unchanged. ([#137](https://github.com/noicework/corpuskit/pull/137))
- Composing an agent ask answer no longer fails on a model that refuses structured output, which the platform answers with 412. When the structured request fails, composition asks again for a plain answer with the same prompt and instructions, and the citation check is unchanged. ([#136](https://github.com/noicework/corpuskit/pull/136))

A camera button, key or drag still ends the drift without pausing the map. ([#135](https://github.com/noicework/corpuskit/pull/135))

### Security

- Link checks go only to public HTTP and HTTPS addresses. A link with credentials, a local or single-label hostname, a private, loopback, link-local, shared, multicast or reserved IPv4 address, or an IPv6 address outside global unicast (mapped, NAT64, 6to4, unique local and documentation addresses included) is refused. Every DNS answer must be public, and an empty or mixed answer is refused. Redirects are followed by hand, at most three, and each is checked again, DNS included. Two gaps remain. The check resolves the host itself and `fetch` then resolves it again, so a host that changes its DNS answer in between (DNS rebinding) could still reach a private address. And website-source page fetches, which changed-page refresh now also uses, still go through plain `fetch`, which follows redirects and applies none of these checks. ([#129](https://github.com/noicework/corpuskit/pull/129))
- The portal list no longer shows every public portal to anyone who asks. `GET /api/tenants` now lists a portal the caller can read only when they are a platform administrator or owner, hold a role on it directly or through a group, or are on the portal's own hostname. An anonymous visitor on the platform domain gets an empty list. A cross-portal ask that names no portals reaches the same portals and is refused when there are none. The switcher beside a portal's logo is drawn only when there is another portal to go to, or for someone who can create portals. See [Portal list](https://github.com/noicework/corpuskit/blob/main/docs/RBAC.md#portal-list). ([#109](https://github.com/noicework/corpuskit/pull/109))

([#61](https://github.com/noicework/corpuskit/pull/61))
- **Seal existing tokens as a separate step.** Once this release has deployed and passed verification, set `BINDING_KEY_MIGRATE=true`, then check that `bindingEncryption.plaintext` and `unavailable` are both 0 in the admin overview. Sealing waits for a verified release so that an automatic rollback never meets tokens it cannot read. ([#61](https://github.com/noicework/corpuskit/pull/61))
- `/api/health` gains a coarse `bindingsReady` flag, always present on Cloudflare and elsewhere only when false. ([#61](https://github.com/noicework/corpuskit/pull/61))
- New optional settings, all off unless set: `PLATFORM_DOMAIN` (default `corpuskit.org`), `OPERATOR_API_KEY` and `OPERATOR_ID` (default `operator`), and `EXTERNAL_LOGIN_ISSUER`, `EXTERNAL_LOGIN_JWK`, `EXTERNAL_LOGIN_NAME` and `EXTERNAL_LOGIN_START_URL`. Changing `PLATFORM_DOMAIN` does not move DNS routes or carry sessions across. ([#61](https://github.com/noicework/corpuskit/pull/61))
- Email assignments are now bound to their identity source. An atomic migration marks existing assignments as Entra. ([#61](https://github.com/noicework/corpuskit/pull/61))
- **Rollback to 2026.9.17 is not safe once any token is sealed:** that release would send the sealed token as the credential. Once external sign-in has created assignments, do not roll back to a release that ignores their identity source, even with external sign-in turned off; prefer a forward fix. Before either, rolling back has effects: 2026.9.17 ignores portal status and limits, so suspended and read-only portals serve and accept changes again, and its next portal registry write forgets retired slugs, so a new portal could take a deleted portal's slug and the records still stored under it. ([#61](https://github.com/noicework/corpuskit/pull/61))
